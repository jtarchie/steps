# internal/web

`internal/web` (echo + `html/template` + one CSS file + a vendored htmx, all `go:embed`ed) serves the browser UI over the same state the CLI writes. The rules that keep this from becoming a second product:

- **web sits above pipeline**, like trigger: it reaches execution only through `pipeline.RunJob`, never into agent/resource/merkle. depguard enforces it.
- **Recording is the runner's job.** `RunJob` attaches a store-backed bus when the caller supplied none, so EVERY run persists its events, not just watched ones. A run started from a terminal and one started from the browser leave the same record.
- **The live view and the post-hoc view read the same rows.** SSE polls `run_events` by sequence number rather than subscribing to the in-process bus — that is what lets the UI show runs another process started, and what stops a live view and a replayed one from drifting. The corollary the live path keeps breaking: **anything the server draws for a finished step, the stream has to draw too.** A step that appears mid-run gets `data-toggle` (the toggle handler is delegated on the document, so a row appended later is clickable), keeps its `open`/`container` classes when it finishes, and receives the agent's answer — all three were missing, and each one alone made a reader reload the page.
- **Every page that shows changing state refreshes itself, and htmx is what does it.** A region carries `hx-get="{{.Nav.URL}}" hx-trigger="every 2.5s [!document.hidden]" hx-select="#itself" hx-swap="outerMorph"` and names the rest of the page's changing parts — the metaline, the queue, `#nav-tabs` — in `hx-select-oob`: the page is its own API, one GET re-renders it, and only the named elements are swapped. Three details are load-bearing and none is a default. **`outerMorph`** reconciles the DOM instead of replacing it, which is what lets a region holding a form (the approvals reason box, a question's answer) be refreshed at all, keeps focus and selection, and makes an unchanged region a no-op; a plain `outerHTML` swap empties an input every 2.5 seconds. **`[!document.hidden]`** stops a forgotten background tab polling forever. And nothing a swap replaces may carry view state: the jobs board's list/graph choice lives on `<body data-view>` with CSS, because a `hidden` attribute on the swapped element itself snapped back to the server's answer under a reader who had chosen otherwise. Overlapping polls need no guard — htmx's `hx-sync` defaults to `drop`. Two things this replaced, and both were the reason for it: the job, approvals, questions, resources and overview pages did not refresh AT ALL (a run triggered while the job page was open appeared only on reload), and the jobs board and runs page each carried a hand-written copy of the poll loop that had already drifted apart. `liveregion_test.go` is the probe that keeps it honest: it renders a page, changes the state behind it, renders again, and fails for every line that appeared outside a region `hx-select`/`hx-select-oob` names — so a new page, or a new stateful section on an old one, fails until htmx is pointed at it. htmx is VENDORED into `static/`, never a CDN: this server is expected to run where there is no route to one.
- **A run is a TREE, and the tree is minted, not derived.** `run_events.step_id`/`parent_step_id` carry it (see [../events/CLAUDE.md](../events/CLAUDE.md) for why the merkle chain cannot). `buildRunView` folds events into a flat `Steps` list — still what run-level questions are asked of — and `linkTree` hangs each on its container; the template recurses over `Roots`.
- **Agent prose is untrusted, and `prose.go` is the boundary.** It is a SECOND goldmark converter, deliberately not `docs.go`'s: that one renders this repo's own embedded docs and may trust them. Raw HTML and `javascript:` are closed by goldmark's defaults; images are rendered inert (a beacon URL in a review is an outbound GET on page open) and heading ids are not generated (an agent must not mint an anchor that collides with `#step-N-name`). The one place the live path uses `innerHTML` is this renderer's output, because its whole contract is that the output is safe — shipping a second markdown parser to the browser would be the riskier choice, and would drift.

`internal/events` is the leaf that carries run events here — see [../events/CLAUDE.md](../events/CLAUDE.md).
