# internal/testpostgres

**A real Postgres for tests, with no docker daemon.** `testpostgres.Start(settings)` runs Postgres 17 from `embedded-postgres`' binaries on a free loopback port with a random superuser password, and `Stop` removes it. It replaced a `postgres:17-alpine` container started through `dockerapi`, which made every Postgres test skip on a machine with docker down — the conformance suite among them.

- **The first run on a machine downloads the binaries** (to `~/.embedded-postgres-go`, from Maven Central); every later run uses the cache. A fetch that fails returns `ErrUnavailable` and the caller skips, the way a missing docker daemon did. Any other `Start` error is a failure, and so is that one when `STEPS_REQUIRE_POSTGRES=1` is set (`RequireEnv`), so a run that must not pass by not testing Postgres cannot.
- **Root is `ErrUnavailable` before the attempt**, because `initdb` refuses uid 0 and no configuration can work around that. The rule lives in the fixture rather than in one test, so `internal/store/postgres`'s `TestMain` — which would otherwise `os.Exit(1)` on a `docker:dind`-as-root worker — skips cleanly too, and the skip reason a root run prints is the one every consumer already reports. `STEPS_REQUIRE_POSTGRES=1` still makes it a failure.
- **A server that cannot add is unavailable too.** `Start` asks every server for `SUM` of two bigints of 200 and skips (or fails under `STEPS_REQUIRE_POSTGRES=1`) unless it says 400. The `linux-arm64v8-alpine` 17.5 binaries answer `400<<64`: found when `examples/release.yml`'s gate ran in `docker:dind` on an arm64 laptop and three usage-rollup tests failed with `bigint out of range`. Real Postgres on that platform is fine; only this test build is not.
- **`Fast` is for tests, `nil` is for measurements.** `Fast` turns fsync off and widens `max_connections`; `task loadtest` with `STEPS_LOADTEST_DB=postgres` passes none, because durability off would flatter the numbers.
- **One server per test process**, in `os.TempDir()/steps-testpg/<pid>/`. `Start` sweeps directories whose pid is gone and signals their postmaster, but only if `ps` still calls that pid a postgres — a run killed outright never reached its own `Stop`.
- **Test-only, enforced by depguard** (`TestSSHDTestOnly`'s deny list), like `testdocker`.
