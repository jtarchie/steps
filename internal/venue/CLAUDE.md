# internal/venue

**The `aws://` and `gcp://` venues are the surfaces no emulator can test.** LocalStack, Moto and fakecloud all stop at the SSM control plane — none implements the session data channel, because it terminates at `amazon-ssm-agent` ON the instance and AWS has never specified it — and no emulator speaks the IAP relay protocol at all. `internal/venue/ssmdial` and `internal/venue/iapdial` are ports, and their fake-agent/fake-relay tests encode the same reading as each client, so a shared misreading passes both sides (iapdial's known instance: CONNECT_SUCCESS_SID is length-prefixed bytes, which two community Go clients misread as a uint64). `hack/aws-fixture.sh up` provisions a real AWS fixture (bucket, instance profile, launch template, one `t4g.small` (free only on an account created before 2025-07-15; otherwise it draws down signup credit), a FIS role) and prints the environment for the opt-in tests: protocol conformance (`./internal/venue/ssmdial`), transport and the acquisition rungs (`./internal/venue`), a pipeline end to end (`./e2e`), the artifact bench (`task bench:artifacts`, both fixtures at once, every hop held to byte and disk budgets read off `run_placements`), and a REAL spot reclamation via `aws:ec2:send-spot-instance-interruptions` — the only way to exercise IMDS → draining frame → re-placement. `hack/gcp-fixture.sh up` is the GCP mirror (firewall rule for the IAP range only, spot instance template with `DELETE`, one `e2-small`) feeding `STEPS_TEST_GCP_*` tests of the same shape, with `instances.simulateMaintenanceEvent` as the FIS stand-in — on a spot instance it IS a preemption, and whether the simulated path matches a real reclaim byte-for-byte is exactly what the fixture test verifies. Each `down` destroys everything its `up` made; the AWS security group has no inbound rules at all (the zero-inbound claim asserted by omission), while the GCP rule admits exactly `35.235.240.0/20 → 22` — the honest difference between the two transports.
