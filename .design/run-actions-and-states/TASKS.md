## Foundation

- [ ] **Held job: a manual trigger runs**: this is a behaviour bug and ships first, on its own. `skipIfPaused` (`internal/web/runner.go:437`) drops every claimed row of a held job, because the claim cannot tell a manual row from a poll's. The fix: a manual row bypasses the breaker gate, while a trigger-poll or webhook row is still skipped. The open question is how the claim learns a row is manual. Recommended: a `manual` bit on the queue row, with a `schemaVersion` bump. Rejected: the in-memory `forced` map pattern, because a manual trigger lost on restart would come back as a silent skip, which is the bug again. Also rejected: parsing `reason`, which task *Queue reasons* rewrites. Done when a test enqueues manually on a held job and sees a run, and a poll-enqueued row on the same job is still skipped. _Modifies: `LocalRunner.skipIfPaused`, `drainOne`, queue store facet + sqlite + storetest._
- [ ] **State chip vocabulary**: one `st-*` class, glyph and colour per state from the IA table. `queued` is `○ --faint`, renamed from `pending` in *display only*; the store keeps `pending`. `aborted` is `■ --dim`. `errored` is `! --red`. New `st-paused` is `⏸ --blue`, and new `st-held` is `⊘ --red`. `statusWord` maps `pending` to `queued`. The overview's unpaused pipeline reads `active`. This establishes the visual direction, so review it before the page tasks. Done when `statusvocab_test.go` asserts each state's word and glyph are rendered (the colour alone is not enough). _Modifies: `app.css` `.st-*` rules, `render.go` `statusWord`, `graph.go` node glyphs, `overview.html`. ## Interactions & States
