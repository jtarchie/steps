# tools/mutants

`task mutate-pkg PKG=./internal/foo [SINCE=rev]` runs mutation testing over one package — `tools/mutants sweep`, which replaced gremlins as the runner because gremlins ran a package's WHOLE suite, docker included, against every mutant (venue: 11 hours); sweep runs each mutant against only the tests whose own coverage profile executes it, docker ones last and serially, and writes gremlins' report shape. It and `task cover-diff` exist because an untested layer once shipped green; triage what they print rather than gating on them. **Mutation testing cannot gate a commit — a survivor needs judgment — so it runs as a periodic sweep, and `tools/mutation-ledger.json` is what makes "periodic" mean something with no scheduler and no CI**: one row per package with the commit it was last swept at, so `task mutate-stale` can rank what has drifted most. **Measuring and triaging are separate, because they cost differently by two orders of magnitude** (merkle: two minutes to measure, ninety to triage): `task mutate-all` MEASURES every package unattended — hours, for a night the machine sits idle, resumable — and triages nothing, while the `mutation-sweep` skill works through one package's survivors (where to run it, how to sort a survivor into e2e-killed / equivalent / real gap, what to record). `task` itself ends on one line when a sweep is due and says nothing when none is; that line is the whole scheduler. Efficacy in the ledger is a floor that only rises; a drop is a finding, not a number to overwrite.
